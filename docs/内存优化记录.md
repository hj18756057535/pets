# 内存优化记录（2026-09-28）

改动：已有宠物时只创建桌宠 WebView；陪伴空间、玩具窗口首次使用时创建。跟随鼠标不需要玩具窗口。动画将最多 72 张帧画布改为复用一张 192×208 缓冲，仍然先按原尺寸裁出单帧再绘制，避免相邻帧串入。取消预览或换宠时清空旧缓冲、图片源和定时器。

陪伴空间第一次加载期间的更换宠物请求会排队，在页面就绪后打开导入对话框。关闭面板仍保留未保存的表单；使用过的窗口暂不自动销毁，因此之后的内存会高于刚启动时。

本机正式 EXE 对比，使用同一只本地宠物、60% 缩放、免打扰、独立数据目录；旧版主面板关闭后等待 12 秒，两版都只显示桌宠，采样三次取平均。没有调用工作集整理。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| PetDesk 及其 WebView 子进程数 | 9 | 7 |
| 私有提交内存 | 368.0 MiB | 213.1 MiB |
| 工作集合计（含共享页面重复计算） | 730.3 MiB | 446.8 MiB |

私有提交内存减少约 42%。它不是独占物理内存，也不同于任务管理器默认列；工作集合计同样不能直接当作独占物理内存。结果是本机快照，不保证所有宠物、驱动和 WebView2 版本下相同。

原始报告位于忽略提交的 `artifacts/memory-before-verified-20260928/memory.json` 与 `artifacts/memory-after-hidden-20260928/memory.json`，含 EXE SHA-256、逐进程数据和主面板可见性检查。复现入口：`tools/measure-memory.ps1`。

验证：36 项 JavaScript 测试、5 项 Rust 测试、33 项面板真实窗口检查通过；覆盖首次按需打开面板并执行更换宠物、动画透明像素、释放画布、跟随不分配玩具、放球取回、右键菜单和源码启动器退出。正式安装包、便携 ZIP 已生成并核对 SHA-256。

## 2026-10-13：隐藏窗口的内存预算与动画暂停

- 桌宠、陪伴空间和玩具窗口隐藏或最小化后，同步 WebView2 控制器的可见性，并请求 `MemoryUsageTargetLevel.Low`；恢复显示时切回 `Normal`。使用实际顶层窗口状态判断，不能直接依赖 WebView2 控制器的 `IsVisible`：Tauri 隐藏父窗口后，该标记可能仍为真。同步后浏览器能发出 `visibilitychange` 并节流后台定时器。旧运行时不支持接口时保留原行为。
- 保留陪伴空间的文档和未保存表单；不自动销毁窗口。停止互动时将隐藏玩具窗口缩为 1×1 逻辑像素，避免取消放球后保留全屏绘制区域，下次互动会重新设置尺寸。
- 隐藏桌宠、隐藏陪伴空间或切到其他页面时暂停相应宠物动画绘制，重新显示时恢复。
- 内存页只统计 PetDesk 及其 WebView2 子进程，同时展示进程数、工作集合计与私有提交。后两者都不能直接当作独占物理内存。

这轮改动主要降低使用过界面后退回后台的占用，已有宠物时的启动窗口数不变。WebView2 的浏览器、渲染、GPU 等多进程仍会存在；不通过关闭沙箱、禁用 GPU 或定时清空工作集来减少显示数字。低内存预算允许浏览器回收缓存或换出页面，实际收益取决于运行时和使用场景。

依据：[Microsoft WebView2 性能建议](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/performance)、[MemoryUsageTargetLevel 接口](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/icorewebview2_19)。

验证：39 项 JavaScript 测试、24 项 Rust 测试和 48 项真实窗口检查通过。窗口检查覆盖原生内存预算读回、浏览器可见性事件、关闭后保留草稿、重新打开恢复预算、隐藏/显示桌宠、取消全屏放球后缩小表面、重复取球和手动内存整理。测试使用隔离数据目录，受限环境无法创建 WebView2 后在本机环境完成。

最终开发版冒烟场景中，完成换宠、互动后关闭面板等待 2 秒，未调用手动工作集整理：工作集合计从 674,553,856 降至 627,884,032 字节（减少约 44.5 MiB）；私有提交从 707,719,168 降至 688,091,136 字节（减少约 18.7 MiB）；进程数仍为 9。报告位于 `artifacts/tauri-smoke-1791822808496/smoke-panel.json`。这是含测试图片生成与多次窗口操作的短时快照，不是修改前后对照基准，也不能作为正式版启动内存或长期降幅的保证。此次未重新打包安装程序。

## 2026-10-14：三只宠物与资源复用

支持一只主宠和两只额外伙伴同时出现、独立拖动、保存位置及分别替换或移出。额外伙伴使用仅绘制宠物的小窗口；主宠继续负责提醒气泡和玩具互动，避免复制提醒状态和后台服务。

- 共用 Rust 主进程、现有后台检查循环和 WebView2 数据目录。真实窗口测试读取 `BrowserProcessId`，确认三只宠物使用同一浏览器进程；各自渲染进程仍有额外开销。
- 相同精灵图的压缩字节通过内容摘要和弱引用缓存复用；移出后不靠缓存强行保留素材。不同窗口的图片解码和绘制缓冲仍独立分配。
- 移出会销毁对应原生窗口、释放后端引用，并等待窗口移除后再允许复用槽位；本地导入文件保留。隐藏全部宠物时，额外窗口同样暂停动画并请求低内存模式。
- 额外选择及位置单独原子保存到 `companion-pets.json`，不覆盖主宠选择。限制槽位、重复项和资源路径；损坏配置保留原文件并记录日志。

验证：39 项 JavaScript 测试、27 项 Rust 测试和 60 项面板真实窗口检查通过，两个额外窗口均完成画布绘制检查。覆盖通过界面导入、第四只拒绝、独立移动、位置存储读取、隐藏/显示、替换、移出与立即重新添加，以及共享浏览器进程。报告：`artifacts/tauri-smoke-1791947136773/smoke-panel.json`。真实多屏拖动和长期运行仍需日常环境验证；此次未更新发布安装包。
