# GitHub 发布准备

## 源码仓库

源码提交包含 `src-tauri/`（包含 Cargo.lock，排除 target 和生成的 icons）、`src/`、`ui/`、`assets/`、`tools/`、`test/`、`docs/`、`package.json`、`package-lock.json`、README、LICENSE 和启动脚本。

`.gitignore` 排除依赖、缓存、`.data/` 中的个人提醒和设置、`.local-pets/` 中的宠物素材、测试截图及 `release/`。不要使用 `git add -f` 强行添加这些目录。忽略规则不能撤回已经上传的文件。

本地核对后提交：

```powershell
git status --short
git add .
git diff --cached --stat
git commit -m "Initial PetDesk release"
```

在自己的 GitHub 账号下创建空仓库，再使用 GitHub 页面提供的远程地址设置 `origin` 并推送。不要把示例用户名当作真实仓库地址。

## 提供普通用户下载的版本

```powershell
npm.cmd ci --cache .npm-cache
npm.cmd test
npm.cmd run package
```

`release/` 下会生成带版本和架构标识的 Tauri 便携版 ZIP、NSIS 安装包、各自的 SHA-256 校验文件及便携版解压目录。打包使用本机 Windows Rust MSVC 工具链，不进行跨平台编译。

在 GitHub 仓库的 Releases 页面新建版本，将 ZIP、安装包及对应的 `.sha256` 文件作为附件上传。发布说明写明系统及架构、功能、已知限制。这里的操作只生成本地产物，不会自动创建 Release 或上传。

普通用户下载 **PetDesk 的 ZIP 附件**，不要下载 GitHub 自动生成的 **Source code**。完整解压后双击 `PetDesk.exe`，不需要 Node.js、npm、Python 或命令行。也可右键 EXE 创建桌面快捷方式，或运行随包提供的 `创建桌面快捷方式.vbs`。部分电脑禁用了 Windows Script Host，此时使用右键方式即可。

便携包还包含使用说明和快捷方式脚本，请完整解压后运行 EXE。Windows 需要 WebView2 Runtime；安装版缺失时可下载安装，便携版需系统已有 WebView2。不要在压缩包内直接运行，不要放进需要管理员权限才能写入的系统目录。移动目录后需要重新创建快捷方式。

## 版本与数据

更新版本号时运行 `npm.cmd version patch --no-git-tag-version`，同时更新并提交 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 和 `src-tauri/tauri.conf.json` 的版本。升级前从托盘退出旧版，将旧目录的 `.data/` 复制到新版 EXE 所在目录，即可保留个人数据；先备份，不要在旧目录内直接覆盖升级。

首次启动不附带第三方宠物，用户可在界面从 Codex Pets 导入。项目的 MIT 许可证不包含宠物作者的素材许可。当前便携包尚未代码签名，Windows 可能显示未知发布者提示；对外正式推广前可考虑代码签名。尚未提供自动更新。

当前已在开发机验证；面向更广泛用户发布前，应在未安装 Node.js 的干净 Windows 机器上测试启动、宠物导入、会议提醒和退出。
