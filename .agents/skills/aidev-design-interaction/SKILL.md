# 交互设计

读取已有需求、交互说明和设计系统。本轮尚未完成的设计直接更新；已实现页面有新的业务交互要求时，按主流程建立关联前序的变更说明。不为调用 Skill 本身新建计划、编号或原型。完整开发由 $aidev-manage-development 串起。

- 按用户目标组织入口、页面层级、主要操作和完成反馈，说明角色及数据范围。字段引用业务定义，控件类型不能替代业务含义。
- 连接页面与业务状态，覆盖本次适用的加载、空态、错误、权限、校验和重复提交等情形。刷新恢复、未保存离开、异步重试等按实际需要设计，不擅自加功能。
- 复用现有组件、术语、布局和设计约束。明确需要的筛选、排序、分页、反馈及键盘可达性。全新视觉方向可先做少量组件/交互样例，确定方向再铺开页面。
- 界面实现遵循项目规则和现有技术栈，复用已有设计资料；仅做沟通设计时不提前铺代码。
- 需要原型时说明要验证的问题、启动方式、Mock 数据和未实现部分；示例不当成真实规则，演示不代表接口或业务完成。
- 为关键用户任务准备人工验证的角色、数据、操作和预期。默认只做代码、静态和非浏览器测试，只有用户明确要求时才运行浏览器、Playwright 或截图验证。
- 页面行为维护在对应功能的需求主档；实现方案写入同任务简称的开发设计并引用需求，遵循主流程的功能目录约定。未变业务定义直接引用；历史功能的新增交互在本次变更文档记录差异，不覆盖旧设计决定。真实人工结果由人提供，不代填通过。
