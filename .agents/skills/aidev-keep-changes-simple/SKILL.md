# 复用优先，保持简单

先确定当前要解决的问题和可验证结果，再决定最小必要改动。此约束伴随实际工作，不增加固定流程、审批或报告。

- **先找再写**：搜索同模块已有组件、服务、类型、工具、依赖和测试。能通过现有入口或小幅扩展解决时直接复用；说明真正缺少的能力再新增。不要复制错误实现或不适用的旧项目包袱。
- **只做当前范围**：不预留未要求的功能、配置、扩展点、插件系统或兼容层。一个用途不为了“以后可能用”增加通用框架；已有简单清晰代码不顺便重写。
- **复杂度要有依据**：新增分层、依赖、缓存、队列、锁或微服务必须解决本次真实问题。能用现有模块和普通函数清楚表达就不升级架构；必要的授权、校验、事务和数据完整性不能以精简为由删除。
- **改动可追溯**：每项改动应对应当前需求或本次引入的问题。保留无关改动和格式；确需扩大范围时先说明理由。用户明确要求的清理按授权边界执行。
- **文档跟随行为**：未实现和本轮开发中的内容更新本轮文档；已实现功能有新需求时，用关联前序的变更文档记录差异，不复制未变规则。不为调试复制计划、规格或报告；需求正确则修代码。
- **用结果检查自己**：完成前看 diff 是否有重复实现、多余接口、无效兜底和未用配置；删减本次引入的多余部分，运行相关行为测试，不以行数或覆盖率作为唯一目标。
- **输出简明且可核验**：说明完成内容、必要取舍、实际测试和未验证项。不要堆砌执行流水账，不隐藏失败或关键未知；不另建“简化报告”。

信息不足先检查现有资料。只有影响结果的关键歧义才提问，已有授权内的局部决定继续推进。
