# AI 协作日志与定期整理

这项能力适用于每一个接入 Kit 的应用开发项目。日志保存在各自项目，每条用统一格式和一个主类型，定期再归纳共性。

## 随手记录

- 使用当前项目的 `docs/feedback/YYYY-MM-DD.md`，首次有内容时创建，同日追加。日期按项目本地时区；标题固定为 `## [类型] 简短主题`，同日同名主题补时间或业务限定词，不强制编号。
- 在一次有实质内容的操作结束或形成结论时，按下方格式简要记录用户要求/纠正、调试现象、关键尝试（含无效尝试）和结果/待办。小需求、一次报错修复、局部调整也适用；每个字段一句话即可，由 AI 顺手填写，不增加审批步骤或单独状态表。
- 同一问题的连续调试合并成一条，保留关键转折和用户决定；新问题再追加。不要逐工具调用写流水账，也不记录“继续”“好的”等单纯确认。只读分析有值得保留的结论时也可记录。
- 用简短摘要忠实保留用户原意；推测的根因明确写“推测”或“待查”。按需要附相关文件、命令或已有任务链接，不复制全部输出、不保存完整聊天，不记录凭证、个人及客户敏感数据。
- 日志不代替功能需求、设计和计划；行为变化仍按主流程维护原文档。已有详细日志照常保留，不为统一格式迁移历史记录；替换通用 Skill 时保留项目日志。

## 五种主类型

| 类型 | 记录什么 | 示例 |
|---|---|---|
| 需求 | 新增功能、业务规则变化或明确的开发目标 | 增加订单筛选；修改审批规则 |
| 纠正 | 用户纠正 AI 的理解、做法或规范执行 | 不要额外创建 DTO；需求理解反了 |
| 排障 | 代码、测试、环境或外部依赖的异常定位过程 | 保存失败；编译报错；连接超时 |
| 优化 | 已有行为的实现、使用体验或协作流程改进 | 减少重复查询；简化日志格式 |
| 经验 | 已验证、值得复用的做法或技术限制 | 找到可靠的测试入口；确认某工具边界 |

每条只选一个主类型，以触发本次操作的主要原因判断。用户报告功能故障通常归“排障”，明确纠正 AI 的理解或做法才归“纠正”；业务行为变化归“需求”，保持目标而改进方法归“优化”。排障产生经验时优先在原条目结果中说明，不为凑“经验”类型再复制一条。类型名保持以上固定值，前端/后端/环境等影响范围放在主题或关联文件中，不另设必填维度。

## 固定格式

标题含类型，正文只固定三个字段：`背景`（要求/现象）、`处理`（实际尝试和决定）、`结果`（实际验证和待办）。每字段单独一行，长内容可继续缩进；字段内容不能因追求简短而只写“已完成”。有实际关联文件、命令或前序日志时，可追加 `关联`，不要求无关条目填“无”。

```markdown
## [类型] 简短主题
- 背景：用户要求、纠正或实际问题。
- 处理：关键尝试与采取的办法；仅讨论时写尚未实施。
- 结果：实际验证、当前结论或未解决项。
```

示例（实际项目首次发生记录时再写，不预建空模板）：

```markdown
# 2026-10-27 AI 协作日志

## [排障] 编辑后字段未清空
- 背景：用户反馈“清空备注后没有保存”。
- 处理：先查请求已提交 null，再定位后端更新策略；按已确认的清空契约调整。
- 结果：定向单元测试通过，实际页面待人工验证。

## [纠正] 单个 ID 不必包装 DTO
- 背景：用户指出此次接口增加了多余包装。
- 处理：复用原参数类型。
- 结果：相关编译通过。
```

## 按需整理

- 有重复问题、需要沉淀的经验或用户明确要求时再整理已有日志，不因跨周就生成报告；没有值得整理的内容就跳过。
- 按最新 `review-YYYY-MM-DD.md` 中已整理到的日期接续，并补看有实质更新的旧条目和已标记的待办；首次整理则使用可访问日志。不另建进度注册表、不每次扫描全部聊天。没有可访问材料就说明范围限制。
- 有内容时在同目录写简短的 `review-YYYY-MM-DD.md`：列出本次覆盖日期、常见问题/有效做法、尚待解决问题，以及少量值得讨论的 Skill 或流程优化线索，链接原日志标题或文件。没有新内容就跳过，不生成空报告、不重复提醒旧建议。
- 按五种主类型统计本次新增条目，再按实际问题归纳主题、影响范围和优化落点；旧格式只在整理结果中归类，不回填全部历史日志。明确新增条目数与旧条目补充数，补看旧记录不增加事件数量。相同问题的重复讨论不能当作多个独立问题，单次案例不冒充高频趋势。
- 区分项目专属问题、已有规则未执行和通用规则缺失。优化线索简述证据、建议落点、适用边界和可行验证；优先复用已有 Skill，不自动修改通用规范、业务需求或人工验收记录。用户已明确授权的局部修复继续执行，不因整理新增审批环节。

## 项目与调度范围

- 每个应用项目只维护自己的日志与整理结果，Kit 不作为所有项目的原始对话仓库。要沉淀通用经验时，将指定项目中已确认且脱敏的线索汇总到 Kit，并保留来源。
- 日志与按需整理由项目规则和 Skill 驱动，依赖当前执行的 AI 遵守规则；不是完整聊天自动采集服务。本次接入不安装后台任务，无人值守整理需要用户另外提出具体调度要求。
